# Юнит-тесты сервисов

Зависимости сервисов подменяются сгенерированными gomock-моками. Каждый кейс
создаёт свой controller и описывает Arrange → Act → Assert. Неожиданные вызовы
зависимостей приводят к ошибке теста; порядок проверяется там, где он важен
(например, сохранение файла → ошибка БД → удаление файла).

Чистые вычисления совместимости, классификация и методы моделей проверяются
напрямую: у них нет зависимостей для подмены. Рабочий код и инфраструктурные
интерфейсы ради тестов не меняются.

Из корня проекта, повторная генерация после изменения интерфейсов:

```sh
go generate ./internal/service/unit_tests
```

Проверка с измерением покрытия **рабочего пакета сервисов**:

```sh
go test ./internal/service/unit_tests \
  -coverpkg=./internal/service \
  -coverprofile=/tmp/totallyswipes-service.cover
go tool cover -func=/tmp/totallyswipes-service.cover
```

Требуемый минимум — 60% statements. `-coverpkg` обязателен: тесты находятся
в отдельной папке. Сгенерированные моки в процент покрытия сервиса не входят.
