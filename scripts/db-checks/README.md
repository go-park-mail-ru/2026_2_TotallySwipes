# Проверки PostgreSQL

Запускать из корня репозитория. Нужны работающий Docker Desktop и Docker Compose.
Все инструменты, включая psql и pgbench, выполняются внутри контейнера.
Рабочая БД проекта не используется.

## Проверка доступов

```bash
bash scripts/db-checks/check-access.sh
```

Поднимает отдельный PostgreSQL, применяет миграции и права, проверяет подключения
каждой роли, неправильные пароли, разрешённые запросы и ожидаемые отказы с SQLSTATE
42501 «недостаточно прав». Затем сохраняет логи и удаляет стенд. Мониторинг для этой проверки не запускается.

## Нагрузочное тестирование

```bash
bash scripts/db-checks/load.sh read-history
bash scripts/db-checks/load.sh send-message
```

Каждая команда самостоятельно поднимает новый PostgreSQL, применяет миграции и права,
запускает exporter, Prometheus и Grafana, выполняет выбранную нагрузку и удаляет стенд.

- `read-history` — последние 50 сообщений случайного чата; результат упорядочен по seq.
- `send-message` — атомарное увеличение seq и вставка сообщения; после нагрузки
  проверяются уникальность позиций, отсутствие пропусков и согласованность счётчиков.
- `all` — оба сценария последовательно на одном стенде.

По умолчанию каждый сценарий запускает 1, 5 и 10 клиентов по 60 секунд каждый.
Нагрузка работает под `chat_app`. Перед каждым запуском администратор восстанавливает
10 тестовых чатов по 1000 сообщений. Это тоже видно на графиках; границы измерения
печатаются в логах. Кеш БД при подготовке не сбрасывается.

Чтобы оставить стенд и посмотреть графики после теста:

```bash
bash scripts/db-checks/load.sh all STAY_ALIVE
```

Без `STAY_ALIVE` стенд удаляется после теста, при ошибке и при Ctrl+C.
С `STAY_ALIVE` стенд сохраняется в том числе при ошибке для диагностики.
Логи сохраняются в обоих режимах.
Одновременно запускать два нагрузочных стенда нельзя: они используют одинаковые порты.

Короткая проверка и изменение параметров:

```bash
PGBENCH_DURATION=5 PGBENCH_CLIENTS="1 2" bash scripts/db-checks/load.sh all STAY_ALIVE
```

## Grafana

- Дашборд: http://localhost:3000/d/postgres-basics.
- Вход: `admin` / `grafana_test_only`.
- Папка PostgreSQL  «PostgreSQL — базовые метрики».
- Prometheus: http://localhost:9090; цель `postgres` должна быть UP.

При чтении смотреть подключения, транзакции и чтение блоков. При отправке —
INSERT/UPDATE, транзакции и подключения. Выбрать интервал теста; обновление каждые
5 секунд, скорость считается за минуту. Нулевой deadlock нормален: обычное ожидание
блокировки не является взаимной блокировкой.

Запись на дашборде — строки в секунду, а не дисковый I/O. TPS, задержки и ошибки
смотреть в итогах pgbench. Это SQL-нагрузка, а не проверка полного API приложения.

## Артефакты и остановка

```text
arifacts/check-access/<проект>/run.log
arifacts/load/<проект>/run.log
arifacts/pgbench/<проект>/<сценарий-дата>/clients-*.log
arifacts/postgres/<проект>/postgres-*.log
```

Для отчёта сохранить TPS, среднюю задержку, ошибки и скриншоты Grafana для каждого
числа клиентов. `arifacts` исключена из Git; нужные фрагменты для сдачи выбираются отдельно.

При `STAY_ALIVE` скрипт печатает имя проекта и готовую команду остановки:

```bash
docker compose -p ИМЯ_ПРОЕКТА -f scripts/db-checks/compose.yml --profile monitoring down --volumes
```

Стенд временный: после удаления контейнеров данные БД и история графиков исчезнут,
а артефакты на компьютере останутся. Пароли в Compose предназначены только для стенда.
Подробнее о метриках и логировании: [monitoring/README.md](monitoring/README.md).
