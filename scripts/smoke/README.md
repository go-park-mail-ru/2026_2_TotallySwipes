# Проверка фотографий перед выкладкой

Из корня репозитория:

```sh
python3 scripts/smoke/photos.py
```

Нужны Docker Compose, Go и Python 3 (без дополнительных Python-пакетов).
Docker должен иметь доступ к образу `dhi.io/minio:latest`, как в основном Compose.

Сценарий собирает текущий backend, поднимает отдельный проект
`totallyswipes-photo-smoke`, применяет все `db/migrations/*.up.sql` и запускает API.
Используются порты 25432, 26379, 29000 и 28080. Они должны быть свободны.
Настройки БД, Redis и MinIO заданы явно; `docker.env` и `.env` не используются
для подключения к основному стенду. После проверки тестовые контейнеры и их
данные удаляются. Не используйте имя этого Compose-проекта для постоянных данных.

Проверяется:

- регистрация тестового пользователя;
- автоматическое создание бакета backend-ом;
- загрузка двух JPEG из `db/data/cats` через multipart API;
- скачивание по исходной подписанной ссылке, Content-Type и совпадение SHA-256;
- запрет анонимного чтения;
- перестановка фотографий;
- удаление фотографии и фактическое исчезновение объекта из MinIO;
- запрет удаления последнего фото и сохранность его объекта.

Сценарий тестирует HTTP на localhost. Внешний адрес и firewall VM, HTTPS,
сохранность данных при перезапуске и PNG/WebP требуют отдельных проверок.

# Смоук-тест логов

Нужны Python 3 и запущенный backend с PostgreSQL и применёнными миграциями.
Сценарий не создаёт пользователей: отправляет login со случайным неизвестным email.

Из корня проекта для API в Docker:

```sh
python3 scripts/smoke/logs.py --compose docker-compose.yml --env-file docker.env
```

Для локального API:

```sh
python3 scripts/smoke/logs.py --api http://localhost:8080 --log-file logs/backend.log
```

Проверяет ответ 401, заголовок `X-Request-ID`, HTTP- и SELECT-логи в
`backend.log` с этим ID, поля HTTP-записи, длительности, отсутствие повторяющихся
JSON-ключей и отсутствие пароля запроса в файле. Ждёт появления записей до 5 секунд.
При ошибке завершается с ненулевым кодом. Контейнеры не запускает и данные не очищает.
